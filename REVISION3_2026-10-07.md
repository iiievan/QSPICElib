# Ревизия 3: сходимость статических стендов

Второй пользовательский прогон сохранён в `SECOND_RUN_2026-10-07.txt`
и `BAS316/tests/second_run_2026-10-07/`,
`IRF7328/tests/second_run_2026-10-07/`.

BAS316: 20 PASS; горячий `.tran` прекращается с
`Timestep too small(1.25e-19) at t=0`.
IRF7328: AC — 3 PASS; DC завис после неудачных Gmin/source stepping
и перехода в pseudo transient. Новых чисел RDS/VTH/Qg/switching нет.

Изменения:

1. Горячая утечка BAS316 измеряется DC-развёрткой от 0 до −75 В,
   при прежних 150 °C и пределах 30/50 мкА.
2. DC IRF7328 переведён с идеального задания тока на развёртку напряжений
   через 1-Ом резисторы. Измерения снимаются при точных заданных токах.
   Напряжения этих резисторов исключены из RDS/VTH/VSD.
3. Runner поддерживает DC FIND WHEN с координатой; добавлены 4
   теста парсера, которые являются синтетическими примерами.
4. GNU timeout дополнен `--kill-after=5s`. Это ограничивает ожидание
   после TERM; на пользовательском Windows/Git Bash ещё не проверено.
   Код 137 отмечается как timeout / forced termination.
5. Модели, температуры, точности `.options` и критерии `.expect`
   не изменены. RonX=7,47 остаётся неподтверждённым кандидатом.

**QSPICE здесь не запускался.** Статический обход не является доказательством
исправления горячего transient BAS316 или универсальной сходимости MOSFET.
WARN по динамике выключения также не устранены.

Порядок следующего прогона, из корня в Git Bash:

```bash
TEST_TIMEOUT_SEC=60 KEEP_RAW=1 ./run_tests.sh BAS316
TEST_TIMEOUT_SEC=60 KEEP_RAW=1 ./run_tests.sh IRF7328
```

При наличии GNU timeout принудительное завершение после 60 с ожидания
получает ещё до 5 с. Передать свежие `.out` и `*.qspice.log`/`*.qpost.log`
из основных каталогов tests; исторические подпапки повторно не нужны.
Не применять широкие taskkill по имени процесса: могут остановиться
другие пользовательские расчёты.
