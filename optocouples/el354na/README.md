# EL354NA — стенды проверки модели QSPICE

Шесть редактируемых схем проверяют входные светодиоды, коэффициент передачи тока, выходной транзистор, ёмкость, переключение, работу на переменном сигнале и температурные зависимости модели EL354NA. Python запускает расчёты, проверяет измерения и создаёт `report.md` с графиками matplotlib.

Схемы находятся в `tests/*.qsch`. Это источник каждого стенда: их можно открывать и изменять в QSPICE. Подключённая модель — `EL354NA.txt`. Исходные `.cir` не нужны: перед каждым запуском они автоматически формируются из `.qsch`.

## Быстрый запуск в Windows

1. Установите QSPICE и Python **3.10 или новее**. Для Python должен работать `py -3` либо `python` в командной строке.
2. Распакуйте папку целиком. Оставьте модель, `tests`, `datasheets`, скрипты и `tests.json` на своих местах.
3. Если нужен прокси, скопируйте `proxy_settings.example.cmd` в `proxy_settings.cmd` и заполните строку `SUITE_PIP_PROXY`. При прямом подключении ничего заполнять не нужно.
4. Запустите `setup.cmd`. Он создаёт `.venv` и устанавливает matplotlib с зависимостями **в эту папку**, не в системный Python. Настройку достаточно выполнить один раз или после изменения `requirements.txt`.
5. Запустите `run_all.cmd` и дождитесь завершения 14 расчётных случаев.
6. Откройте `results/<дата UTC>/report.md` в редакторе с просмотром Markdown, например VS Code. Картинки подключены относительными путями. Для передачи отчёта отправляйте всю папку конкретного запуска.

Если QSPICE находится в нестандартной папке, запустите в командной строке:

```cmd
run_all.cmd --qspice-dir "C:\Program Files\QSPICE"
```

Скрипт также учитывает переменную окружения `QSPICE_DIR`, папку `%USERPROFILE%\QSPICE`, стандартные Program Files и каталог QSPICE из `PATH`. Нужны три файла из одной установки: `QUX.exe`, `QPOST.exe`, `QSPICE64.exe`. Для движка повышенной точности можно передать `--engine 80`, тогда нужен `QSPICE80.exe`.

### Прокси

Личные настройки храните только в `proxy_settings.cmd`:

```cmd
set "SUITE_PIP_PROXY=http://LOGIN:PASSWORD@proxy.example:PORT"
```

Замените LOGIN, PASSWORD, адрес и PORT своими значениями. Специальные символы в логине и пароле требуют URL-кодирования. В `.cmd` знак `%` пишется как `%%`: пароль `a@b` записывается `a%%40b`. Шаблон содержит пояснение. `setup.cmd` сохраняет уже существующий файл настроек; файл исключён из Git и диагностики.

## Что остаётся после расчёта

При успешном запуске структура минимальна:

```text
results/<дата UTC>/
    report.md
    figures/
        01_led_ctr_dc.png
        02_output_dc.png
        03_input_capacitance_ac.png
        04_switching_tran.png
        04_switching_tran_edges.png
        05_ac_polarities_tran.png
        06_temperature_dc.png
```

Никаких HTML-отчётов и копий входных схем не создаётся. Измерения, параметры, контрольные суммы исходников и конфигурация сохранены внутри Markdown, в служебном комментарии. Он позволяет пересобрать текст отчёта, не сохраняя отдельные JSON рядом с картинками.

Если любой случай получил FAIL/ERROR или не удалось создать графики, остаётся `diagnostics` со **всеми** полученными QRAW выбранного запуска, нетлистами, логами и CSV. Успешные случаи такого запуска тоже сохраняются: удаление происходит только после проверки всего набора и записи отчёта. Если расчёт прерван, уже созданные файлы остаются для диагностики.

При WARN предельные проверки пройдены, но типовое значение отличается больше допуска методики. WARN отражается в отчёте и сам по себе не считается неудачей запуска; QRAW удаляется. Чтобы сохранить QRAW даже при успехе:

```cmd
run_all.cmd --keep-raw
```

Коды возврата: `0` — выбранный набор обработан успешно, возможны WARN; `1` — FAIL/ERROR или ошибка графиков; `2` — ошибка подготовки/команды; `130` — прерывание.

## Как выполняются тесты

Для каждого стенда QUX получает нетлист непосредственно из `.qsch`. Значения `.step` разворачиваются в отдельные расчёты: вместо одного многосерийного QRAW создаётся один случай на одно значение параметра. Значения перебора в `tests.json` должны совпадать с `.step` схемы; несовпадение даёт понятную ошибку. Если `.step` в схеме отключён, Python всё равно использует заданный в `tests.json` перебор и меняет соответствующий глобальный `.param` в расчётном нетлисте.

Модель читается из пути, указанного в схеме, и включается в расчётный `.cir`. Исходные QSCH и модель не изменяются. Для этих схем поддерживается подключение файла через `.lib`, `.include` или `.inc` без секций; вложенные подключения разрешаются относительно подключающего файла.

QSPICE рассчитывает случай. QPOST вычисляет **все `.meas` из схемы по полному QRAW**. QUX экспортирует указанные в `tests.json` сигналы в CSV с запрошенными 10 000 интервалов; фактическое число экспортированных точек записывается в отчёт. matplotlib создаёт PNG. Таким образом, цифры не вычисляются по пикселям рисунка или по разреженному графическому экспорту. Отсутствующие, неоднозначные, нечисловые измерения и неполный экспорт считаются ошибкой.

### Как читать результат

| Обозначение | Значение |
|---|---|
| PASS | Заданный критерий выполнен. |
| WARN | Типовое значение вышло за допуск сравнения методики; это не нарушение предела даташита. |
| FAIL | Предельный, функциональный или внутренний критерий не выполнен. |
| ERROR | Нет достоверного измерения, экспорта или законченной обработки. |

В отчёте каждое правило имеет основание: **предел даташита**, **типовое значение**, **согласованность модели** или **критерий схемы**. Допуски симметрии и сравнения с типовыми значениями задаёт `tests.json`; изготовитель такие допуски не устанавливает.

Даташит: [EL354N-G Series, Rev.6](datasheets/EL354N(A)(TA)-VG.pdf), выпуск 01.09.2016. Номера страниц ниже совпадают с печатными номерами в PDF. Параметры таблицы на стр. 3 относятся к **25 °C**, если не указано другое условие. Типовые графики показывают характер зависимости, а не гарантированный разброс всех деталей.

## 01 — светодиоды и CTR

**Схема:** `tests/01_led_ctr_dc.qsch`. Три случая: `GAIN=0.5`, `1`, `1.5`. Температура 25 °C, `THERMAL=0`, VCE=5 В. Входной ток меняется от 0.1 до 30 мА. Две ветви включают оптопару с противоположными направлениями входного тока.

CTR — отношение выходного тока коллектора к входному току светодиода: `CTR=IC/IF`. В модели `CTR1M` задаёт это отношение при IF=1 мА и VCE=5 В. Для ранга **EL354NA** даташит задаёт 50…150% в точке IF=±1 мА. Поэтому GAIN=0.5/1/1.5 представляет три выбранных варианта передачи, а не степень старения.

Что проверяется:

- `CTR_POS`, `CTR_NEG` — заданный GAIN при IF=1 мА в обеих полярностях. Допуск воспроизведения заданного параметра модели — ±0.01 в единицах IC/IF.
- `CTR_SYM` — максимальная разница CTR между полярностями; критерий модели ≤0.001.
- `VF20_MAX`, `VF20_REV_MAX` — напряжение на светодиодах при 20 мА; предел даташита 1.4 В в обеих полярностях.
- `VF20_TYP` — сравнение с типовыми 1.2 В, допуск методики ±0.06 В. `VF1_DIAGNOSTIC` — контрольная точка при 1 мА, ориентир 1.05±0.15 В для диагностики кривой.
- `LED_SYM1`, `LED_SYM20` — симметрия напряжений двух входных ветвей, допуск методики 5 мВ.
- `CTR_FIG3_*` — контрольные значения дополнительного узла при нескольких IF. Они записываются в отчёт без предельной приёмки.

**С чем сверять:** стр. 3, VF и CTR; стр. 4, Fig. 1 при 25 °C и Fig. 3 для VCE=5 В.

На графике абсолютный CTR отображается в **процентах**. Для сопоставления формы с Fig. 3 отдельная панель нормирует каждую кривую: `CTR(IF)/CTR(5 мА)`. В таблице `.meas` значение CTR=0.5 означает 50%, а не 0.5%. Узел `ctr_fig3` в схеме имеет собственное масштабирование и напрямую эту нормировку не заменяет.

Этот тест показывает, сколько выходного тока даёт заданный входной ток. Он нужен, чтобы не подменять всю рабочую кривую единственным паспортным значением CTR при 1 мА.

## 02 — насыщение и темновой ток

**Схема:** `tests/02_output_dc.qsch`. Три GAIN: 0.5/1/1.5. Температура 25 °C. В схеме одновременно работают две ветви насыщения с противоположным входом, ветвь утечки без света и ветвь выходной характеристики.

Что проверяется:

- `VCE_SAT`, `VCE_SAT_NEG` — напряжение открытого фототранзистора при IF=±20 мА и нагрузке, задающей IC≈1 мА. Предел 0.2 В; типовое значение 0.1 В сравнивается с допуском методики ±0.03 В.
- `IC_LOAD`, `IC_LOAD_NEG` — фактический ток этой нагрузки. Ориентир 1 мА, допуск ±0.04 мА подтверждает условия измерения.
- `ICEO_20V` — ток коллектора при **IF=0** и VCE=20 В. Предел 100 нА при 25 °C.
- `IC_CURVE_AT_5V` — дополнительная точка выходной характеристики IC(VCE), снятой при `IF_CURVE=5m`.

**С чем сверять:** стр. 3, строки VCE(sat) и ICEO; стр. 4, Fig. 5/6 — характер IC(VCE). В этом стенде IF_CURVE=5 мА, поэтому три GAIN не представляют три входных тока с рисунков даташита. Абсолютное совпадение всех выходных кривых как критерий не заявляется.

Насыщение важно, потому что открытая оптопара должна опускать входное напряжение достаточно низко. Темновой ток важен по обратной причине: закрытая оптопара не должна заметно стягивать подтяжку и мешать получить HIGH. Приближённо падение на подтяжке равно `ICEO × Rpull`.

## 03 — входная ёмкость

**Схема:** `tests/03_input_capacitance_ac.qsch`. Один случай, 25 °C. Между входами источника задан DC=0 В, AC=1 В. Частота меняется от 100 Гц до 1 МГц.

`INPUT_I_1KHZ` и `INPUT_I_MAX` измеряют модуль входного тока **в одной точке 1 кГц**. Название INPUT_I_MAX обозначает проверку допустимого значения в этой точке, не максимум всей кривой. `CIN_1KHZ_PF` пересчитывает ток в пикофарады:

`Cin = |I(Vac)| / (2 × π × f × |Vac|)`.

**С чем сверять:** стр. 3, Input capacitance: VAK=0 В, f=1 кГц, типовое значение 50 пФ и максимум 250 пФ. Типовое сравнение использует ±5 пФ; эквивалентный максимальный ток при AC=1 В — примерно 1.571 мкА. Графики тока и эффективной ёмкости имеют логарифмическую шкалу частоты, отмечена точка 1 кГц.

Это ёмкость **входных светодиодов**, а не CIO между изолированными сторонами. Она влияет на реакцию входа на быстрые изменения напряжения; сама по себе эта проверка не определяет задержку оптической передачи.

## 04 — переключение

**Схема:** `tests/04_switching_tran.qsch`. Один случай, 25 °C, `CTR_TEST=0.5`, `TAU=2u`. На вход подаётся импульс 2.7 мА, питание выходной цепи 2.2 В, RL=100 Ом. Установившийся ток коллектора получается около 2 мА, VCE около 2 В.

`VCE_ON` измеряется на плато 60…65 мкс. Из него вычисляется `IC_ON_DERIVED=(2.2−VCE_ON)/100`; внутренний допуск 2 мА±0.1 мА проверяет, что фиксированные пороги фронтов подходят этому режиму.

`T_RISE_IC` измеряет рост тока, то есть **падение напряжения** коллектора с 2.18 до 2.02 В. `T_FALL_IC` измеряет падение тока, то есть **рост напряжения** с 2.02 до 2.18 В. Эти уровни соответствуют IC=0.2 и 1.8 мА: примерно 10 и 90% от 2 мА. В отчёте есть общий график и увеличение двух фронтов.

**С чем сверять:** стр. 3, tr/tf≤18 мкс при VCE=2 В, IC=2 мА, RL=100 Ом; стр. 5, Fig. 10 — схема и определения фронтов. IF=2.7 мА выбран для получения указанного рабочего тока этой моделью; это не отдельное требование изготовителя.

Если меняете GAIN, TAU или нагрузку, сначала проверьте установившийся IC. При другом плато прежние уровни 2.18/2.02 В перестают быть 10/90%; нужно согласованно изменить `.meas`, правила и пояснение методики. TAU — параметр модели, не паспортное типовое время оптопары.

## 05 — обе полуволны и переход через ноль

**Схема:** `tests/05_ac_polarities_tran.qsch`. Один случай, 25 °C. Источник — синус **24 В амплитудой**, 50 Гц, входной резистор 22 кОм. Выход подтянут через 10 кОм к 3.3 В.

- `V_POS`, 5 мс: оптопара включена на положительной полуволне; критерий ≤1 В.
- `V_NEG`, 15 мс: она включена на отрицательной полуволне; критерий ≤1 В.
- `V_ZERO`, 10 мс: около перехода через ноль входного света мало, выход должен подняться; критерий ≥3.2 В.

**С чем сверять:** назначение AC input на стр. 1, CTR при IF=±1 мА на стр. 3. Это функциональный тест схемы; для порогов 1/3.2 В отдельной строки в даташите нет. При подключении к микроконтроллеру реальные VIL/VIH берутся из его даташита с учётом питания и температуры.

Подтяжка 3.3 В задаёт доступный HIGH. Когда фототранзистор включён, его ток должен преодолеть подтяжку и получить LOW. Когда свет пропадает, выход должен вернуться к HIGH. **Здесь фаза не отключается**: проверяется только отпускание около перехода синуса через ноль. Схема не содержит сетевой источник питания, ограничитель тока или ШИМ.

## 06 — температура −35…+60 °C

**Схема:** `tests/06_temperature_dc.qsch`. Пять случаев IF_TEST: 0.5/1/5/10/25 мА, VCE=5 В, `THERMAL=1`. `.dc TEMP` меняет реальную температуру симулятора с шагом 1 °C; контрольный узел `actual_temp` подтверждает, что перебирается именно температура.

**С чем сверять:** стр. 4, Fig. 4 — normalized IC(T) при VCE=5 В. Все пять кривых нормированы на **одну общую** точку IC при IF=5 мА и 25 °C. Опорная ветвь `Xref` имеет IF=5 мА и `THERMAL=0`, поэтому её передаточная характеристика остаётся опорной при переборе температуры. График `V(ic_norm)` использует эту нормировку и логарифмическую вертикальную шкалу, как Fig. 4.

Что записывается:

- `ACTUAL_TEMP_MIN/MAX`: подтверждение диапазона −35…+60 °C.
- `CTR_AT_25/COLD/HOT` и `CTR_NEG_AT_*`: CTR обеих полярностей при +25/−35/+60 °C.
- `CTR_SYM`: симметрия входных ветвей во всём диапазоне.
- `F_T_COLD/HOT`: CTR при −35/+60 °C, делённый на CTR **той же кривой** при 25 °C. Это коэффициент температурной поправки, другая нормировка, чем IC_NORM.
- `IC_NORM_AT_25`: контрольная точка нормированного IC.
- `VF_AT_COLD/25/HOT`: напряжение светодиода, визуальная диагностика Fig. 1. Температурный закон диода отдельно по этому рисунку не подогнан.
- `ICEO_20V_AT_25/60` и `ICEO_3V3_AT_60`: утечка при указанных напряжениях и температурах.

Предельный критерий ICEO≤100 нА применяется только к `ICEO_20V_AT_25`. **Для +60 °C этого допуска в даташите нет.** Модель использует постоянное Rdark=1 ГОм; она выдаёт примерно 20 нА при 20 В и 3.3 нА при 3.3 В при любой температуре. Плоская кривая утечки отражает это предположение, а не измеренную температурную стабильность детали.

CTR(T,IF) получен приближённым воспроизведением типовых кривых Fig. 4. Проверка даёт наглядную температурную диагностику и подтверждает согласованность схемы; она **не устанавливает гарантированный минимальный CTR при −35…+60 °C**. Допуски производственного разброса и срок службы требуют дополнительных исходных данных и испытаний.

## Что этот набор не проверяет

Старение, вероятностный разброс партии, пробой, изоляция, саморазогрев и температурная зависимость времени переключения здесь не моделируются. В таблицах даташита есть характеристики, для которых эти стенды не дают результата, например BVCEO/BVECO, RIO, CIO и fc. Их нельзя считать пройденными по этому отчёту.

Изменение GAIN задаёт разные варианты начального CTR. Чтобы проверить старение изделия, нужен отдельный сценарий снижения CTR с обоснованной степенью деградации и критериями работоспособности изделия. Для температурной приёмки изделия также нужны его реальные нагрузки, питание и пороги входов.

## Изменение стендов и выбор отдельных тестов

Откройте `.qsch` в QSPICE, внесите правки и сохраните. Следующий запуск сформирует новый нетлист. Подключение модели в схемах задано относительно `tests`: `../EL354NA.txt`. Порядок выводов модели: входы LED, коллектор, эмиттер; для корпуса это 1, 2, 4, 3.

`tests.json` задаёт список схем, перебор параметров, экспортируемые сигналы, диапазон независимой переменной и численные правила. Если меняете `.step`, диапазон анализа, имена `.meas` или сигналы, обновите соответствующие поля JSON. Стиль конкретных графиков определён в `make_figures()` файла `run_suite.py`; при новой топологии нужно согласовать также их физический смысл. Простое переименование другой оптопары без проверки условий и даташита не делает этот набор универсальным.

Запуск одного стенда:

```cmd
run_all.cmd --bench 06_temperature_dc
```

Нескольких:

```cmd
run_all.cmd --bench 01_led_ctr_dc --bench 04_switching_tran
```

Отчёт явно перечисляет только выбранные случаи. Сравнивая результаты разных запусков, проверьте SHA-256 модели, схем, `tests.json`, скрипта и инструментов QSPICE в отчёте: изменения исходников или расчётного движка могут менять результат.

## Если что-то не получилось

Сначала откройте `report.md`: там указан проблемный случай и ошибка. Не удаляйте `diagnostics`. Запустите:

```cmd
collect_diagnostics.cmd
```

Он найдёт последний запуск с диагностикой и создаст небольшой `diagnostics_<дата>.zip`. В архив входят отчёт, сохранённые параметры, экспортированные нетлисты и текстовые логи не более двух проблемных случаев. QRAW, CSV осциллограмм, `.venv` и настройки прокси не включаются.

Для конкретной папки:

```cmd
collect_diagnostics.cmd "results\20261009T120000.000000Z"
```

Если QRAW рассчитаны, а ошибка была в чтении измерений или экспорте, можно повторить обработку без нового расчёта:

```cmd
reprocess.cmd
```

Будут снова вызваны QPOST и QUX для **сохранённых CIR/QRAW**, с сохранённой конфигурацией запуска. Изменение исходной QSCH или модели не меняет эти результаты: для новой схемы нужен `run_all.cmd`. Если QRAW для какого-либо случая не был создан, повторная обработка его не восстановит.

Пересобрать только Markdown по встроенным измерениям и имеющимся картинкам:

```cmd
rebuild_report.cmd
```

Обе команды принимают папку результата первым аргументом; без неё выбирается последний подходящий запуск. `rebuild_report.cmd` не создаёт PNG заново: после удаления QRAW для этого нужен новый расчёт.
