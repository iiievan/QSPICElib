# EL354NA: шесть схем вместо отдельных схем для каждого измерения

**Этап: подготовка стендов для сборки `.qsch`. Новые нетлисты и модель v0.2 — кандидаты, ещё не запускались в QSPICE.**

Комплект предназначен для `optocouples/el354na` в библиотеке. Сначала вы собираете схемы по шести `.cir`, сохраняете `.qsch` с теми же именами и присылаете комплект. После проверки экспорта подключаем Python, автоматические сценарии, matplotlib и отчёт Markdown. Сейчас новых запускающих скриптов в этом комплекте нет; общий запуск существующей библиотеки не изменён.

## 1. Сколько схем действительно нужно

В прежней библиотеке было **7 нетлистов и 22 строки проверки**, а не 22 разных схемы. Некоторые строки проверяли несколько значений перебора. Мы объединяем LED, опорный CTR и кривую CTR(IF) в одну схему. Получается **5 схем для всех прежних проверок**, плюс **1 новая температурная**.

| Схема в `tests/` | Что собрать | Прежние строки проверки | Для сравнения |
|---|---|---:|---|
| `01_led_ctr_dc` | Два оптрона: положительное и обратное подключение LED; VCE=5 В | 10 | PDF стр. 3: VF и CTR; стр. 4, Fig. 1 и Fig. 3 |
| `02_output_dc` | Четыре ветви: два насыщения, тёмная утечка, выходная кривая | 4 | PDF стр. 3: VCEsat и ICEO; стр. 4, Fig. 5/6 |
| `03_input_capacitance_ac` | Один оптрон с AC-источником на входе | 2 | PDF стр. 3: Cin при 0 В и 1 кГц |
| `04_switching_tran` | Один оптрон, импульсный вход, выход с RL=100 Ом | 3 | PDF стр. 3 и стр. 5, Fig. 10 |
| `05_ac_polarities_tran` | Один оптрон на синусе 24 В пик, 50 Гц | 3 | Дополнительный функциональный тест обеих полуволн |
| `06_temperature_dc` | Два направления входа, опорный оптрон и две тёмные ветви | Новые измерения | PDF стр. 4, Fig. 4; температура −35…+60 °C |
| **Итого** | **6 схем** | **Все 22 прежние строки сохранены по смыслу** | |

В новых нетлистах есть дополнительные измерения и больше точек графика. Итоговое количество чисел в будущем отчёте будет больше 22 — это нормально. Сопоставление каждой старой строки с новой схемой и измерением записано в `bench_map.json`. Это описание для будущего Python-скрипта, а не готовый исполнитель тестов.

## 2. Что положить в библиотеку

Из архива возьмите папку `optocouples/el354na`. Внутри:

- `EL354NA.txt` — кандидат v0.2 с опциональной температурной поправкой;
- `tests/` — шесть исходных нетлистов, сюда же сохранить шесть `.qsch`;
- `datasheets/EL354N(A)(TA)-VG.pdf` — исходный Everlight EL354N-G Rev.6;
- `references/figure4_temperature_ratios.csv` — приблизительные температурные коэффициенты;
- `bench_map.json` — карта старых проверок и новых стендов;
- `README.md` — эта памятка;
- `references/PREPARATION_CHECK.md` — выполненные проверки подготовки и их пределы.

Полную библиотеку, корневой runner и PC814 этот комплект не заменяет. Старую папку `EL354NA` с результатами не удаляйте до успешного запуска новых схем. Если разместить рядом две версии, прежний runner может найти обе — новый комплект пока предназначен для ручной сборки схем и проверки.

Разделение остальных компонентов на `mosfets`, `diodes`, `ics`, `optocouples` и корневой последовательный запуск выполняем позже. Если затем потребуется запуск всех компонентов, корневой `.cmd` сможет последовательно вызывать локальные runner-скрипты и суммировать их коды завершения. Расчёт и формирование отчёта останутся внутри каждого компонента.

## 3. Как собирать `.qsch`

1. Схемы сохраняйте в `optocouples/el354na/tests/`, рядом с соответствующим `.cir`. Например, первая схема — `01_led_ctr_dc.qsch`.
2. Расставьте элементы из электрических строк нетлиста. `X...` означает экземпляр оптрона, `I...` — источник тока, `V...` — источник напряжения, `B...` — вспомогательный источник или монитор. Служебные `.param`, `.step`, `.dc`, `.ac`, `.tran`, `.meas`, `.options` перенесите в текстовые SPICE-директивы. Заголовок-комментарии и `.end` рисовать не нужно.
3. Порядок выводов модели: **A, K, C, E**. Для физического корпуса это **1, 2, 4, 3**. Не менять местами C и E.
4. Сохраните имена цепей, экземпляров и источников из нетлиста. Измерения и будущий Python читают именно эти имена.
5. Все электрические строки нужно либо нарисовать элементами, либо оставить как текстовые SPICE-элементы. Не включайте одну и ту же строку дважды. Для основных ветвей оптрона лучше нарисовать элементы, чтобы стенд был понятен при открытии.
6. В каждом стенде должен использоваться один актуальный `EL354NA.txt`. Относительный путь из `tests/`: `.include "../EL354NA.txt"`.
7. В символе оптрона используйте внешнюю библиотечную модель, а не сохранённую текстовую копию вида `library file: |.SUBCKT ...`. При необходимости укажите внешний файл в свойствах символа. Не оставляйте одновременно две разные реализации одной подцепи.
8. Проверьте экспортируемый нетлист QSPICE: в нём должна оказаться новая реализация с параметром `THERMAL` и функциями `EL354_F...`. Если QSPICE уже разворачивает библиотечную модель в экспорт, отдельная `.include` не должна подключать ту же подцепь второй раз. Пришлите экспорт вместе со схемами — окончательное подключение к автоматизации проверим по нему.
9. Для температурного стенда должны быть экземпляры с `THERMAL=1`, а у опорной ветви — `THERMAL=0`. Сам оптрон остаётся тем же `EL354NA`, новый символ для температуры не нужен.

**Земля — узел `0`.** Не заменяйте глобальные имена цепей словами C/E из формальной записи подцепи: например, внешний источник на выходе должен обращаться к реальному имени `out`, `csat_pos` и т. п. Тестовой утечки `IDARK_TEST` из системного стресс-теста здесь нет: это компонентные стенды.

Во всех B-мониторах выход — напряжение служебного узла, численно представляющее CTR, ток в амперах или безразмерную нормировку. Название оси в будущем отчёте должно отражать физическую величину, а не буквально «В» для любого B-монитора.

## 4. Что делает каждый стенд

### 01 — LED и передача CTR

Положительная ветвь: `Xp led_pos 0 cp 0`. Обратная: `Xn 0 led_neg cn 0`. В обоих случаях источник тока втекает в соответствующий LED-узел; меняется порядок входных выводов модели. `Bled_neg` повторяет ток `Iled_pos` во второй ветви.

DC-развёртка меняет входной ток от 0,1 до 30 мА. `.step GAIN` повторяет её для опорного CTR 0,5 / 1 / 1,5. Точки 1 и 20 мА лежат точно на сетке. Из этих же двух ветвей получаем LED VF, положительный/отрицательный CTR и симметрию.

При +25 °C:

- VF при ±20 мА: типично 1,2 В, максимум 1,4 В;
- CTR при ±1 мА и VCE=5 В соответствует заданному `GAIN`;
- симметрия направлений — структурная проверка этой симметричной модели;
- форма CTR(IF) — сравнение с типичным графиком, а не гарантированная производственная граница.

Имена `CTR_FIG3_...` сохраняют связь со старыми проверками. Узел `ctr_fig3` пересчитывает результат к старой иллюстративной кривой `CTR1M=0.5`. **Это ещё не нормировка графика Fig.3 к единице при 5 мА.** Для непосредственного наложения на Fig.3 будущий Python разделит всю кривую CTR данного запуска на её значение при 5 мА.

График LED: IF по логарифмической оси, VF по линейной. График CTR: IF и нормированный CTR, при необходимости логарифмические оси. Дополнительные точки ниже 0,5 мА показывают продолжение формулы; фит в этой области не подтверждён.

### 02 — насыщение, утечка и выходная кривая

Две насыщенные ветви получают IF=20 мА и нагрузку 4,9 кОм от 5 В: ток коллектора близок к 1 мА. Проверяем положительный вход, дополнительно — отрицательный. При +25 °C прежний предел VCEsat — 0,2 В, типичная диагностическая точка — 0,1 В.

Тёмная ветвь имеет A=K=0 и VCE=20 В. При +25 °C сравниваем ICEO с максимумом 100 нА. Фиксированный 1 ГОм в текущей модели даёт 20 нА; это выбранная модельная величина, а не типичный ток из даташита.

Четвёртая ветвь строит IC(VCE) на диапазоне 0…10 В. `IF_CURVE=5m` — начальная настройка. Позже Python последовательно задаст 1, 5, 10 и 20 мА без дополнительных схем. Для Fig.6 увеличиваем область 0…1 В того же графика; шаг 10 мВ уже предусмотрен. Семейство GAIN можно показывать отдельно от семейства IF_CURVE.

Прежние измерения насыщения и утечки остаются постоянными при развёртке четвёртой ветви. Это нормально: их независимые источники не изменяются. График IC(VCE) — новая диагностика упрощённой зависимости Bphoto; совпадение всех выходных кривых с даташитом ещё не заявлено.

### 03 — входная ёмкость

При VAK=0 подаём AC-сигнал с модулем 1 В. Развёртка 100 Гц…1 МГц содержит точку 1 кГц. Из тока на входе вычисляется Cin. Прежние проверки типичного 50 пФ и максимального 250 пФ относятся только к 1 кГц и +25 °C.

`CIN_1KHZ_PF` дополнительно выдаёт ёмкость прямо в пФ. Для частотного графика Python вычислит `|I|/(2πf|V|)`. Это оценка двухполюсной входной ёмкости, не барьерной ёмкости между входом и выходом.

### 04 — переключение

Сохранён ранее проверенный стенд: RL=100 Ом, питание 2,2 В, входной импульс 2,7 мА, `TAU=2u`. Его рабочая точка близка к условиям таблицы: IC≈2 мА и VCE≈2 В.

Включение фототранзистора — спад выходного напряжения и рост выходного тока. Выключение — наоборот. Графики входного и выходного токов, VCE, увеличение области фронтов дадут наглядную картину.

**Прежние фиксированные уровни измерения времени применяются только при +25 °C.** При изменении температуры меняется CTR и рабочая точка; такой же ток LED уже не обязательно создаёт IC=2 мА. Для температурного времени понадобится отдельное правило установки рабочей точки/вычисления уровней 10–90%. В модели нет данных для изменения TAU или накопления заряда с температурой, поэтому этот стенд пока не доказывает температурное быстродействие.

### 05 — две полуволны

Синус 24 В **пикового** напряжения и 50 Гц, входной резистор 22 кОм, выходная подтяжка 10 кОм к 3,3 В. Проверяем, что обе полуволны включают выход, а около нуля он отпускается. Это независимый компонентный функциональный стенд, не модель сетевого входа S2000.

Прежние критерии: в 5 и 15 мс выход ≤1 В, в 10 мс ≥3,2 В. Их повторение при других температурах — дополнительный функциональный сценарий, а не гарантированные числа из таблицы Everlight.

### 06 — температура

QSPICE выполняет `.dc TEMP -35 60 1`. Пять входных токов: 0,5 / 1 / 5 / 10 / 25 мА. Положительный и отрицательный входы сравниваются при VCE=5 В. Узел `actual_temp` проверяет, что используемая температура действительно соответствует развёртке.

В Fig.4 все токи нормированы к IC при **IF=5 мА и +25 °C**. В стенде для этого есть опорная ветвь `Xref` с IF=5 мА и `THERMAL=0`. При принудительно заданном токе её фотоотклик остаётся прежним опорным значением. Поэтому `ic_norm` можно сравнивать с общей нормировкой Fig.4.

`F_T_COLD` и `F_T_HOT` — другая величина: коэффициент относительно +25 °C **при том же входном токе**. Именно такими коэффициентами поправляется модель. Не путать эти две нормировки.

Дополнительно видны VF LED и тёмные токи при VCE=20 В / 3,3 В. Их присутствие в графиках показывает текущее поведение модели, но пока не означает, что эти температурные зависимости подогнаны к данным производителя.

## 5. Кандидатная температурная модель

У модели остаются четыре вывода A/K/C/E и прежние параметры `CTR1M`, `TAU`. Добавлен параметр `THERMAL`:

```spice
* Прежнее поведение выхода:
Xuut a k c e EL354NA PARAMS: CTR1M=0.5 TAU=2u THERMAL=0
* Приближённая поправка CTR(T,IF):
Xuut a k c e EL354NA PARAMS: CTR1M=0.5 TAU=2u THERMAL=1
```

По умолчанию **THERMAL=0**. Это сохраняет старые уравнения и позволяет сначала проверить совместимость модели в библиотеке. Стенды 01…05 явно начинают с отключённой поправки и +25 °C. Стенд 06 явно включает её. При THERMAL=0 стандартное температурное поведение самих диодов SPICE всё ещё действует.

Поправка при THERMAL=1:

`Iphoto_new = Iphoto_old × F_T(T, I_F)`

`F_T` получен приблизительным ручным чтением Fig.4 из приложенного Everlight Rev.6. Для каждого входного тока значения делятся на значение **этой же кривой при +25 °C**. Поэтому F_T(+25 °C, IF)=1 и прежняя зависимость от IF не меняется. Между точками используется линейная интерполяция коэффициентов по температуре и по току.

| IF | F_T при −35 °C | F_T при +25 °C | F_T при +60 °C |
|---:|---:|---:|---:|
| 0,5 мА | 1,551 | 1 | 0,657 |
| 1 мА | 1,441 | 1 | 0,760 |
| 5 мА | 1,056 | 1 | 0,818 |
| 10 мА | 1,018 | 1 | 0,848 |
| 25 мА | 1,076 | 1 | 0,880 |

Это **приблизительные коэффициенты типичных кривых**, не гарантированные температурные пределы CTR. Оценка точности ручного чтения — порядка 10–15%; уточнение по образцам остаётся отдельной работой.

Полная сетка: температура −55, −35, −20, 0, +25, +40, +60, +85, +100 °C; ток 0,5 / 1 / 5 / 10 / 25 мА. Исходные относительные точки сохранены в CSV. Координаты пикселей в CSV относятся к промежуточному рендеру стр.4 при 260 dpi, с кропом x=1180, y=1190, ширина 680, высота 540. Логарифмическая ось IC даёт примерно 126 пикселей на декаду; отношение вычислено как `10^((y25-yT)/126)`.

За краями токовой/температурной сетки поправка ограничивается ближайшим краем. **Это техническое ограничение интерполяции, а не подтверждённая экстраполяция.** Особенно важно для сетевого стресс-теста: около переходов через ноль ток LED ниже 0,5 мА, где даташит не задаёт температурную кривую. Точная граница обнаружения в этой области требует измерений или отдельного консервативного испытательного сценария.

В этой версии не изменены:

- параметры диодов и их встроенный температурный закон — они не подогнаны к Fig.1;
- `Rdark=1G`: в предоставленном PDF нет температурной кривой ICEO, поэтому новый закон не придуман;
- `TAU=2u` по умолчанию и отсутствие накопления заряда: температурных данных для них нет;
- приближённая зависимость выхода от VCE; температурный коэффициент выведен при VCE=5 В и не подтверждает низковольтные режимы коллектора;
- изоляция, пробой, саморазогрев и производственный разброс: эти свойства новой поправкой не проверяются.

Для предыдущего S2000 stress test нужно различать штатную модель и воздействия. `K_AGE` остаётся множителем исходного CTR. При включении нового температурного закона в настоящем температурном сценарии задаём `K_TEMP=1`, чтобы не учитывать снижение второй раз. `IDARK_TEST` остаётся независимой дополнительной утечкой стенда. Старый успешный отчёт относится к прежнему поведению; для буквального повторения сохраняйте прежнюю модель/THERMAL=0 и прежнюю температуру симулятора. Изменение глобальной `.temp` дополнительно меняет и LED.

## 6. Что прислать после сборки

Нужны шесть файлов `tests/*.qsch` с именами соответствующих `.cir`, экспортированные нетлисты и фактически использованный `EL354NA.txt`. Достаточно прислать эту папку архивом; `.venv`, QRAW и будущие результаты пока не нужны.

Затем:

1. Сверим узлы, полярность источников, подключённую версию модели и условия каждого измерения.
2. Выполним прежние проверки при +25 °C и THERMAL=0; новый кандидат должен сохранить прежние числа в заданных допусках.
3. Повторим +25 °C при THERMAL=1; передача должна совпасть, так как поправка равна единице.
4. Проверим температурный стенд и сравнение с типичными кривыми. Ошибку модели, отсутствие данных и реальную потерю функционального запаса будем показывать разными статусами.
5. Сделаем локальный Python runner: `.venv`, прокси как прежде, последовательные сценарии, matplotlib, `report.md` с относительными PNG-ссылками и полными числами. Для каждого графика укажем страницу/Fig., условия и тип предела.
6. Очистка сохраняет знакомые правила: после успешного расчёта и формирования отчёта только Markdown/PNG; при ошибке все QRAW и журналы, диагностика без тяжёлых файлов.

Ни один будущий отчёт не должен называть совпадение с типичной температурной кривой гарантией работы всех экземпляров −35…+60 °C. Приёмка модели и проверка реального компонента — разные уровни подтверждения.
