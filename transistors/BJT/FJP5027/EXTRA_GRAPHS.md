# Дополнительные графики FJP5027: Fig.5, Fig.6, Fig.7

Распаковать пакет v3 в корень QSPICElib с сохранением каталогов.
Существующие QSCH не перезаписываются. Для Fig.7 используется уже нарисованный
`03_resistive_switching_tran.qsch`: дополнительную схему рисовать не надо.
Исходная модель CANDIDATE_V1 пока сохраняется как исходная точка калибровки.

В папке `transistors/BJT/FJP5027` выполнить:

```bat
run_extra.cmd
```

Будут выполнены **18 новых симуляций**: 9 значений нагрузки, для каждого шаг
1 ns и 0.5 ns. Условия Fig.7: 125 V, IB1=45 mA, IB2=-0.5 A.
По оси X откладывается фактический ток, а не 125/R. QPOST сначала находит
плато IC_ON, затем по тому же QRAW определяет времена на его уровнях 90/10%.
Схема при втором проходе QPOST не меняется; меняются только .meas.

Результат: `extra_results/<UTC>/report.md`.
Компактный архив для отправки создаётся автоматически:
`FJP5027_extra_diagnostics.zip`. QRAW и полный CSV удаляются по умолчанию.
После сбоя отдельного случая очистка тоже выполняется; нативные измерения,
CIR, журналы и компактные NPZ остаются. Флаги --keep-raw/--keep-waveforms
включают сохранение больших данных только явно.

Основной `run_all.cmd` по-прежнему запускает прежние 28 случаев.
Новый прогон не объявляет модель откалиброванной, даже если времена сходятся.

## Только графики 5–6 из уже готового прогона

```bat
run_extra.cmd --overlay-only
```

Последний полный нативный прогон с резистивным и индуктивным стендами при
25 C выбирается автоматически. Можно указать его явно:

```bat
run_extra.cmd --overlay-only --base-run results\20261104T121959.027057Z
```

Если полный прогон отсутствует, показываются только паспортные границы.
Для наложения нужны компактные NPZ версии 2; они входят в обычную диагностику.
В новом отчёте сохраняется отдельная копия использованных данных, чтобы он
пересобирался после перемещения или удаления исходного results.

Пересборка без QSPICE и без QRAW:

```bat
run_extra.cmd --report extra_results\ИМЯ
```

Только подготовка 18 CIR без симуляции:

```bat
prepare_extra.cmd
```

Сбор диагностики старого дополнительного прогона:

```bat
run_extra.cmd --collect extra_results\ИМЯ
```

При нестандартной установке доступен --qspice-dir и переменная QSPICE_DIR.
--cir-only использует сохранённую CIR-топологию вместо получения нетлиста QSCH.

## Как интерпретировать результат

| Рисунок | Что построено | Что можно проверить |
|---|---|---|
| 5 | Векторная паспортная граница IC(VCE) + траектория CIL | Форму траектории выключения; условия наложенного прогона отличаются от PDF |
| 6 | Паспортные SOA DC / 10 ms / 1 ms / 100 us + траектории | Расположение рабочего режима относительно опубликованных границ; автоматического допуска по SOA нет |
| 7 | Две паспортные кривые A/B + нативные ts(IC), tf(IC) | Времена на фактическом токе и их сходимость |

**Fig.5, несмотря на заголовок Switching Time, не содержит оси времени.**
По осям и условиям он интерпретируется как граница выключения индуктивной
нагрузки типа RBSOA. Его нельзя получить как временную характеристику одной
симуляции. Буквальные условия PDF — IB1=3 A, RB2=0, L=1 mH, VCC=20 V.
Текущий CIL имеет IB_ON=0.3 A, L=2 mH, ограничение 400 V и иной способ
выключения; одинаковые условия и приёмка по Fig.5 не заявляются.

**Fig.6 — данные производителя о допустимой области**, а не результат
расчёта разрушения в Gummel–Poon. Успех SPICE за её границами не доказывает
пригодность реального транзистора. Длительность импульса и температура
наложенных траекторий не установлены как соответствующие каждой границе.
Они показаны только для диагностики; SOA PASS не вычисляется.

**У Fig.7 отсутствуют однозначные подписи отдельных линий** ts/tf. Поэтому
они названы curve_A и curve_B; их соответствие величинам не выдумано.
Нет автоматической оценки совпадения по этим двум кривым. Допущения
стенда: 25 C, 5 kHz, два периода, TON=99.995 us, фронт команды 5 ns.
Температура, длительность импульса и определения времён в самом графике
не указаны. 45 mA сохранено как напечатано — не заменено на 450 mA.

При большом требуемом токе модель может не выйти в насыщение с 45 mA базы.
Это видно по IC_ON и VCE_ON. VCE_ON>5 V помечается крестиком и
VCE_ON_HIGH; 5 V — проектный диагностический порог. Пропавшие/отрицательные
пересечения дают INVALID; они не подставляются как нулевые времена.
PASS сходимости означает только, что уменьшение шага мало изменило
измерения. Для этого сравниваются также реальные IC_ON, а не только времена.

## Модель и мастер QSPICE

Мастер QSPICE предназначен для MOSFET, JFET и диодов, а не BJT.
QSPICE уже рассчитывает нашу .model NPN. Проблема — извлечение параметров,
а не формат схемы. Сначала надо откалибровать статические и температурные
характеристики, затем параметры заряда и переключения. Результаты пробного
подбора в Python не заменяют нативную проверку QSPICE.

QSPICE поддерживает MEXTRAM 504, включая саморазогрев. Это возможный путь
при недостаточности простой модели, но потребует дополнительных исходных
данных. Усложнение модели само по себе не даёт правильных параметров.
У текущего PDF нет Zth(t), поэтому переходная тепловая цепь не задана.

## Проверка пакета

Пройдены 34 проверки Python (25 прежних и 9 новых). Проверены нативные
форматы QPOST, привязка порогов к измеренному току, подготовка всех 18
CIR из настоящего пользовательского экспорта QUX, отсутствие усреднения
вертикальных границ, запрет тихой подмены эталона, очистка и компактная
диагностика. Показанные в preview траектории взяты из присланного полного
прогона 20261104T121959.027057Z. **Новый нативный Fig.7 ещё не запускался**:
QSPICE недоступен в среде подготовки. Пилот и повторный QPOST требуют
первой проверки на установленном QSPICE пользователя.
