# FJP5027: QSPICE + Python, первая итерация модели

Этот пакет начинает проверку **FJP5027**.
Он использует четыре уже нарисованных общих BJT-стенда и добавляет один CIR
для насыщения с принудительными IC и IB. Исходные QSCH Python не переписывает.

## Установка в библиотеку

Распаковать архив **в корень QSPICElib**, с сохранением каталогов.
Добавляется `transistors/_common`, заполняется ранее пустой
`transistors/BJT/FJP5027/FJP5027.txt` и добавляются файлы автоматизации рядом.
Общие схемы остаются по существующему адресу:
`transistors/Si/transistor_common_cir_v1/bjt/`.
Если перенести схемы, изменить только `schematic_dir` в `profile.json`.

1. В папке `transistors/BJT/FJP5027` выполнить `setup.cmd`.
2. Выполнить `run_all.cmd`.
3. Открыть самый новый `results/<UTC>/report.md` в просмотрщике Markdown.
4. Для передачи результатов выполнить `collect_diagnostics.cmd`.

Если QSPICE установлен нестандартно:

```bat
set QSPICE_DIR=D:\Tools\QSPICE
run_all.cmd
```

Или:

```bat
run_all.cmd --qspice-dir "D:\Tools\QSPICE"
```

`setup.cmd` требует Python 3 и устанавливает numpy/matplotlib в локальную .venv.
При необходимости можно создать собственный `proxy_settings.cmd` с настройками
окружения pip; никаких чужих паролей/прокси в пакет не включено.

## Что делает запуск

Всего 28 независимых случаев, без `.step`:

| Группа | Условия |
|---|---|
| Рис.1, IC(VCE) | IB=50,100,...350 mA; 25 C; физическая VCE по горизонтали |
| Рис.2, hFE(IC) | VCE=5 V; -25,25,75,125 C; фактическое IC/IB |
| Рис.3, VCEsat(IC) | IC/IB=5; четыре температуры |
| Рис.4, VBEsat(IC) | IC/IB=5; четыре температуры |
| Ёмкость | Cobo при VCB=10 V, 1 MHz; Cibo как диагностика |
| Резистивное переключение | 400 V, 200 ohm, IB1=0.4 A, IB2=-0.8 A |
| CIL | Диагностика 20 V / 2 mH / около 1.5 A; ограничение 400 V |
| Сходимость | 2 ns, 1 ns, 0.5 ns для обоих динамических стендов при 25 C |

Резистивный стенд работает при 5 kHz, 50% и фронте 5 ns: в таблице даташита
не задана частота. Это явно сохранённые условия стенда, а не восстановленные
неизвестные условия производителя. Верхний предел ton сравнивается от 10%
фактического прямого IB до 90% IC. Для ts указан отсчёт от нулевого IB;
для окончательной паспортной приёмки необходимо подтвердить определение ts.

Первый запуск может показать FAIL/INVALID. Это полезный результат: исходная
модель ещё не откалибрована. **Факт завершения симуляции не означает PASS.**

## Модель: что уже есть и чего нет

`FJP5027_CANDIDATE_V1` - самостоятельно составленная начальная Gummel-Poon
модель. Это **не модель производителя и не результат завершённой подгонки**.
BF/IKF/VAF выбраны как стартовые оценки для усиления; CJC оценена по 60 pF
при 10 V; TF оценена по fT=15 MHz. Остальные динамические параметры,
температурные зависимости и насыщение требуют проверки и калибровки.

В архиве пользователя `FJP5027.txt` был пустым. Демонстрационная модель
BENCH_NPN_DEMO в эту проверку не подставляется.

Начальный кандидат может заметно отличаться от крутых участков VCEsat при
большом IC: обычная Gummel-Poon модель ограниченно описывает квазинасыщение
высоковольтного силового BJT. Если простой подгонки не хватит, нужна более
подходящая физическая модель или явно описанная дополнительная ветвь.
Отчёт покажет расхождение; график не будет искусственно исправлен.

## Эталонные кривые

`reference/curves.csv` содержит 2919 точек / 19 кривых. Они извлечены из
векторных полилиний **именно приложенного PDF** Fairchild Rev.A December 2003.
`provenance.json` содержит SHA-256, привязку осей, температуры и допущения.

На рис.1 температура не указана внутри графика; принято 25 C по умолчанию.
У рис.3 и 4 перепутанные/неоднозначные подписи заголовков. Приоритет имеют
подписи осей и условие IC=5 IB: слева VCEsat, справа VBEsat.
Кривые hFE пересекаются при больших токах; температура сопоставлена по их
порядку при малом IC, а не по правому концу.

Для повторного извлечения, только если меняется эталон:

```bat
.venv\Scripts\python.exe -m pip install PyMuPDF
.venv\Scripts\python.exe tools\extract_reference.py
```

Привязка путей жёстко соответствует этой редакции PDF. После изменения PDF
её надо проверить визуально. Толщина линий и разброс изделий не исчезают при
векторной оцифровке. Не интерпретируйте лишние знаки CSV как точность измерения.

## Как читается сравнение

Сплошная линия - оцифрованный типовой график; пунктир - фактический QSPICE.
Линейные/логарифмические оси и пределы совпадают с даташитом.
Показаны RMS, P95, максимальная относительная ошибка и покрытие эталона.
Экстраполяция и сглаживание не применяются. Допуски задаются в `profile.json`;
это критерии проекта, не заявленная точность производителя.

Калибровка на тех же кривых - проверка качества подгонки. Для независимой
валидации нужны дополнительные точки/осциллограммы, не использованные при
подгонке, и в идеале измерения физических экземпляров.
Корректная формулировка: «модель соответствует проверенным характеристикам
в указанных режимах с такими-то ошибками». Фраза «полностью соответствует
реальному транзистору во всех режимах» этим отчётом не обосновывается.

NaN, отсутствующие пересечения, неправильные рабочие токи, знак ёмкости,
недостаточное покрытие и отсутствие сходимости явно видны и не дают PASS.
Измерения времени и энергии берутся QPOST из полного QRAW. CSV для рисунков
экспортируется QUX с отдельным контролем достаточности числа точек;
если ограничение экспорта не позволяет показать короткий фронт, это указано.

## Температура и тепло

`.temp` - изотермический прогон, а не расчёт саморазогрева. В даташите
обозначено TC; при сопоставлении принимается Tj приблизительно равной TC.
Температура кристалла, корпуса и окружающей среды не смешиваются.

Из Fig.8 выведено стационарное RthJC=2.5 K/W. В отчёте есть график снижения
допустимой мощности и оценка Tj=TC+Pavg*RthJC для посчитанной периодической
мощности. Это оценка, не замкнутая электротепловая симуляция.
В приложенном PDF нет Zth(t): Cth и переходную тепловую цепь не выдумываем.

В этой модели не реализованы пробой, вторичный пробой, SOA/RBSOA, старение,
тепловая память. Fig.5 (оси IC/VCE, несмотря на название Switching Time)
не является осциллограммой. У двух кривых Fig.7 нет однозначных подписей
ts/tf: автоматический PASS по ним не формируется.

## Команды

```bat
prepare.cmd
run_all.cmd --only output gain saturation
run_all.cmd --only cap
run_all.cmd --only resistive inductive
run_all.cmd --report results\ИМЯ_ПРОГОНА
run_all.cmd --reprocess results\ИМЯ_ПРОГОНА
collect_diagnostics.cmd
collect_diagnostics.cmd --raw
```

`prepare.cmd` создаёт все CIR и предварительный отчёт только с эталонами:
**QSPICE не запускается**, исходником являются сохранённые CIR-топологии.
Обычный `run_all.cmd` использует QUX для получения нетлиста из твоих QSCH.
Дополнительный стенд насыщения пока запускается непосредственно из CIR;
если нарисовать одноимённый QSCH и положить к общим схемам, он будет выбран
автоматически. `--cir-only` - явный запасной режим, с пометкой в отчёте.

`--report` пересобирает отчёт по сохранённым данным, `--reprocess` повторяет
QPOST и экспорт по сохранённому QRAW. Они не запускают новую симуляцию.
Смена эталонного CSV после прогона блокирует тихую переоценку старых данных.

Коды завершения: 0 - выполнены проверенные критерии либо prepare-only;
1 - изучить отчёт (калибровка/сходимость/неполный расчёт); 2 - ошибка запуска.
QRAW сохраняются для повторной обработки. Сбор диагностики по умолчанию
исключает объёмные QRAW, но включает CIR, параметры, измерения, CSV, рисунки,
модель, конфигурацию и журналы.

## Что проверено при подготовке пакета

Проверены извлечение эталонов, генерация 28 CIR, контракты параметров,
разбор QPOST (включая complex/NaN), запрет экстраполяции, контроль рабочих
режимов, построение и повторная сборка предварительного отчёта.
QSPICE/QUX/QPOST в среде подготовки отсутствуют: нативный запуск,
переходные процессы и совпадение кандидата с даташитом **ещё не подтверждены**.

Проверки Python:

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Расширение на MOSFET / GaN / SiC

Подход к отчётам тот же: отдельный расчёт на параметры/температуру, реальные
физические оси, эталон отдельно от модели, численные ошибки и сходимость.
Но нужны соответствующие FET-стенды, распиновка/драйвер и модель конкретной
технологии. Этот выпуск реализует BJT/FJP5027; он не заявляет готовую
проверку GaN/SiC. Для GaN особенно отдельно проверяются обратное проведение
и dynamic RDS(on), для SiC - условия затвора, температуры и ёмкостей.
