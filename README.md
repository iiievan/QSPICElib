# QSPICE_library

Библиотека поведенческих моделей компонентов для QSPICE с автоматической
проверкой каждой модели по даташиту.

Главная идея: **модель без стенда не существует**. Любая модель — это подгонка,
и единственный способ узнать, насколько она верна, — поставить её в ту же
измерительную оснастку, в которой производитель снимал цифры для даташита.
Поэтому у каждого компонента есть стенд, файл ожиданий и протокол сверки.

---

## Что нужно установить

**QSPICE** — https://www.qorvo.com/design-hub/design-tools/interactive/qspice
По умолчанию ставится в `C:\Program Files\QSPICE`.

**Git Bash** (идёт с Git for Windows) — в нём запускаются тесты.

Больше ничего. Python, PyQSPICE и прочее не требуются.

---

## Быстрый старт

Открыть Git Bash в корне библиотеки и выполнить:

```bash
chmod +x run_tests.sh     # один раз
./run_tests.sh
```

Ожидаемый вывод:

```
Najdeno stendov: 1
======================================================================

--- 74HCT244_test
    ECHO_CORNER    ok
                   1 2 3 4
    A1_VOH         ok
                   4.19999 3.97979 3.83999 3.70199
    A2_VOL         ok
                   0.199806 0.259806 0.330006 0.400206
    ...
======================================================================
VSE STENDY PROSHLI
```

`ok` означает, что измеренное значение уложилось в допуск относительно
даташита. `FAIL` — не уложилось, с указанием номера угла.

Если QSPICE установлен не по умолчанию:

```bash
QSPICE_DIR="/c/Qspice" ./run_tests.sh
```

Обратите внимание на запись пути: в Git Bash диск `C:` пишется как `/c/`.

Другие режимы:

```bash
./run_tests.sh 74HCT244      # прогнать только один компонент
KEEP_RAW=1 ./run_tests.sh    # не удалять .qraw, чтобы посмотреть осциллограммы
```

## Структура

```
QSPICE_library/
├── README.md                       ← этот файл
├── run_tests.sh                    ← прогон всех стендов
└── 74HCT244/                       ← один компонент = одна папка
    ├── 74HCT244.txt                ← сама модель (.subckt)
    ├── datasheets/
    │   └── MM74HCT244-D.PDF        ← даташит, по которому калибровали
    └── tests/
        ├── TEST_README.md          ← откуда взята каждая цифра
        ├── 74HCT244_test.cir       ← стенд: только измеряет
        ├── 74HCT244_test.expect    ← ожидания: что должно получиться
        └── RESULTS.md              ← протокол последнего прогона
```

Разделение стенда и ожиданий не формальность. Стенд отвечает на вопрос
«сколько намерили», файл ожиданий — «сколько должно быть по даташиту».
Вышла новая ревизия даташита — правите одну таблицу, схему не трогаете.

## Как подключить модель к своей схеме

В netlist добавить строку загрузки и вызвать подсхему:

```spice
.lib C:\...\QSPICE_library\74HCT244\74HCT244.txt

X1 IN OEB OUT VCC GND 74HCT244 params: ROH=50 ROL=33.3 TPD=9n
```

Параметры, которые не указаны, берутся по умолчанию из `.subckt`.
Значения по умолчанию — типовые при +25 °C. Для анализа худшего случая
подставляйте набор из угла 4 (см. таблицу в шапке файла модели).

## Формат файла ожиданий

```
# izmerenie  rezhim  dopusk  ugol1 ugol2 ugol3 ugol4
A1_VOH       abs     0.03    4.20  3.98  3.84  3.70
A3_TPLH      max     0.15    14n   20n   25n   30n
```

| Режим | Условие | Когда применять |
|---|---|---|
| `abs` | \|изм − ож\| ≤ допуск | абсолютная величина, напряжения |
| `rel` | \|изм − ож\| ≤ допуск · ож | относительная погрешность |
| `max` | изм ≤ ож · (1 + допуск) | гарантированные **максимумы** даташита |
| `min` | изм ≥ ож · (1 − допуск) | гарантированные **минимумы** |

Суффиксы `p n u m k` понимаются. Если углов в строке меньше, чем шагов
`.step`, последнее значение используется для оставшихся.

Измерение, которого нет в файле ожиданий, помечается в выводе как
`net v .expect` — так вы не потеряете забытую строку.

## Как добавить новый компонент

1. **Создать папку** `<ИМЯ>/` с подпапками `datasheets/` и `tests/`,
   положить туда PDF даташита.

2. **Написать модель** `<ИМЯ>/<ИМЯ>.txt` — один `.subckt`. В шапке обязательно:
   источник и ревизия даташита, версия модели, условия калибровки,
   таблица температурных углов и раздел «чего модель не воспроизводит».

3. **Написать стенд** `<ИМЯ>/tests/<ИМЯ>_test.cir`. Правило: стенд
   воспроизводит **условия измерения из даташита**, а не рабочую схему.
   Для каждой строки таблицы даташита — свой источник, своя нагрузка,
   своё `.meas`. Стенд только измеряет, никаких вердиктов.

4. **Заполнить ожидания** `<ИМЯ>/tests/<ИМЯ>_test.expect` прямо из таблиц
   даташита.

5. **Написать** `<ИМЯ>/tests/TEST_README.md` — для каждого измерения указать
   страницу, таблицу, строку и колонку даташита. Это самая скучная и самая
   ценная часть: через полгода только по ней можно будет понять, откуда
   взялась конкретная цифра.

6. **Прогнать** `./run_tests.sh <ИМЯ>` и калибровать параметры модели, пока
   всё не станет `ok`.

7. **Записать протокол** в `RESULTS.md`.

Имя стенда обязано заканчиваться на `_test.cir` — по этой маске скрипт их
и находит.

---

## Проверка «сломай нарочно»

Перед тем как поверить зелёным `ok`, убедитесь, что стенд вообще способен
поймать ошибку. Испортите одно ожидание в `.expect` — должен появиться
`FAIL` с номером угла. Верните обратно.

Звучит избыточно, но именно так был пойман первый вариант вердиктов:
он показывал правдоподобные результаты, которые не имели отношения
к реальности.

## Автоматический прогон перед коммитом

```bash
cat > .git/hooks/pre-commit <<'EOF'
#!/usr/bin/env bash
./run_tests.sh || {
    echo "Стенды не прошли. Коммит отменён."
    echo "Если это осознанно: git commit --no-verify"
    exit 1
}
EOF
chmod +x .git/hooks/pre-commit
```

Скрипт возвращает 0 при успехе и 1 при любом провале, так что хук работает
без дополнительной обвязки.

## Особенности QSPICE, на которых легко споткнуться

Найдены экспериментально при работе над первым компонентом. В документации
частично есть, но разрозненно.

### `.meas` с TRIG/TARG требует условие уравнением

```spice
.meas TRAN TPLH TRIG V(pin)=2.5 RISE=1 TARG V(out)=2.5 RISE=1    ← так
.meas TRAN TPLH TRIG V(pin) VAL=2.5 RISE=1 ...                   ← ошибка
```

Форма с `VAL=` (как в LTspice) даёт `Expected lhs=rhs`.

### `.meas ... PARAM` при `.step` считает неверно

Строка вида

```spice
.meas TRAN PASS PARAM {if(abs(A1_VOH-VOH_EXP)<0.03,1,0)}
```

выглядит работающей, но при `.step` **параметр внутри выражения заморожен
на значении последнего шага**. Схема при этом степается правильно.

Проверено: при полном совпадении всех четырёх измерений с даташитом
вердикт выдал `0 0 0 1` — «прошёл» только тот угол, чьё ожидаемое значение
случайно совпало с замороженным. Ошибка молчаливая, никаких предупреждений.

Поэтому сравнение вынесено в `run_tests.sh`.

### `.model` ключа пишется без скобок, параметры обязательны

```spice
.model SWUP SW Ron=50 Roff=1g Vt=2.75 Vh=0.2
```

Значений по умолчанию для `Ron`, `Roff`, `Vt`, `Vh` у QSPICE нет.

### TTOL на разрывных элементах

QSPICE считает с адаптивным шагом. Ключи `S` и `if()` в B-источнике —
разрывные: момент переключения находится точно, но **следующая** точка
может оказаться далеко, и `.meas` начинает интерполировать мимо.

Проверено на 74HCT244 без ограничения шага в `.tran`:

```
TTOL=1n    → tPLH = 14,94 нс
TTOL=200n  → tPLH = 16,97 нс   (+14 %)
```

Важная деталь: фронты при этом не искажаются — они сами заставляют решатель
мельчить. Страдают только измерения **по одному пересечению уровня**,
то есть задержки. Картинка выглядит нормально, а число врёт.

### `.step temp` не действует на поведенческие модели

Температурной зависимости у них нет. Температура входит **набором
параметров** — так же, как даташит задаёт её отдельными колонками
гарантированных пределов.

## Запуск вручную, без скрипта

```bash
cd 74HCT244/tests
"/c/Program Files/QSPICE/QSPICE64.exe" -binary 74HCT244_test.cir
"/c/Program Files/QSPICE/QPOST.exe" 74HCT244_test.cir -o out.txt
cat out.txt
```

Посмотреть осциллограммы: `"/c/Program Files/QSPICE/QUX.exe" 74HCT244_test.qraw`

Пересчитать измерения по уже готовому `.qraw`, без повторной симуляции:

```bash
"/c/Program Files/QSPICE/QPOST.exe" meas_script.txt -r 74HCT244_test.qraw -o out.txt
```

Первая строка файла `meas_script.txt` обязана быть комментарием — она
игнорируется. Удобно при подборе критериев годности: прогон с шагом
0,05 нс не бесплатный.
