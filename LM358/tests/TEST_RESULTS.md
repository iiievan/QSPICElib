# LM358 0.1.0-preview — статус проверки

Дата подготовки: 2026-09-19.

**QSPICE/QPOST: НЕ ВЫПОЛНЕНО. Модель не принята как проверенная.**

В доступной среде отсутствуют QSPICE64.exe и QPOST.exe. Фактический вызов
`bash run_tests.sh LM358` остановился с кодом 2 на проверке окружения:
`NE NAJDEN: /c/Program Files/QSPICE/QSPICE64.exe`.
Это не PASS и не электрический FAIL модели. Файлы `.out/.qraw` для LM358
не создавались; старый корневой отчёт не переименован в результат LM358.

## Дополнительная инженерная проверка уравнений

Воспроизводится отдельно, при наличии Python 3, NumPy и SciPy:

```bash
python tools/review_lm358_equations.py
```

Этот необязательный инструмент не нужен для штатных тестов библиотеки.
Он читает B-выражения из `LM358.txt`, решает ограниченный набор уравнений
и интегрирует их методом Radau. Он **не** загружает `.cir` в SPICE и не
проверяет поведение QSPICE, QPOST, `.step`, GUI-символов или pin mapping
полного netlist. Числа ниже нельзя считать фактическими `.meas`.

Динамический fit приближённый: он не повторяет все точки рис.5/7 точно.
Подгонка двух полюсов уменьшила ошибку выброса малого импульса; уровни AC
в средней полосе примерно на 2,7 дБ выше графической прямой. Это записано
как погрешность модели, а не скрыто под статусом «точная модель».

## Что требуется для приёмки

1. Запустить `KEEP_RAW=1 ./run_tests.sh LM358` в QSPICE.
2. Проверить все 11 стендов, особенно DC-servo, AC-парсинг, отрицательные
   температуры и порядок выводов `LM358_DUAL`.
3. Сверить `.out` с таблицей происхождения критериев. Все hard FAIL устранить;
   каждый дополнительный WARN объяснить. Холодный рейтинг намеренно даёт WARN.
4. При изменениях параметров повторить весь компонентный набор; допуски не
   расширять ради PASS. Нужны реальные результаты для калибровки под QSPICE.
5. После этого записать фактический протокол, указав версию симулятора.

Температурная валидация реального LM358 при −35 °C не может быть закрыта
прогоном этой модели: это за пределами рабочего рейтинга указанного компонента.
