# FDS4559 — universal characterization benches

Эта папка намеренно отделена от `tests/`.

- `tests/` — **regression по даташиту**: PASS/WARN/FAIL, воспроизводимые
  критерии пригодности самой модели.
- `characterization/` — **универсальные свипы**: они исследуют поведение
  компонента в типовой оснастке, но не объявляют один конкретный режим
  «правильным» для всех проектов.
- конкретные изделия и их требования живут в `applications/`.

Так библиотека остаётся полезной сама по себе: ни 18 В, ни 24 В, ни ток
конкретного мотора не становятся свойством модели FDS4559.

---

## FDS4559_gate_frequency_sweep.cir

Универсальный complementary-half-bridge из двух кристаллов FDS4559.
Драйверы идеальные; внешний `Rg` — часть исследуемой оснастки.

Базовая оснастка:

```text
VBUS       = 30 V
VGS(N)     = 0 / +5 V
VSG(P)     = 0 / +10 V
load       = resistor to VBUS/2, ~1 A in either state
dead time  = 500 ns
frequency  = 10 / 20 / 50 / 100 / 200 / 400 kHz
Rg_ext     = 10 / 22 / 47 / 100 / 220 / 470 / 1000 ohm
```

`30 V / 1 A` — **не рекомендация для конечного изделия**. Это всего лишь
нейтральная повторяемая fixture: половина рейтинга `VDS=60 V` и умеренный
ток. Все основные величины вынесены в `.param`, поэтому другой проект может
повторить тот же стенд со своими условиями, не меняя модель.

Семь независимых копий полумоста позволяют за один `.step FSW` получить
матрицу `Rg × frequency`.

### Что измеряется

Для каждого `Rg`:

- `P_VSG_PK`, `N_VGS_PK` — успевает ли затвор набрать полную амплитуду;
- `SW_MAX`, `SW_MIN` — успевает ли midpoint реально дойти до обеих шин;
- `IBUS_PK` — пиковый ток шины (нагрузка + capacitive/overlap transient);
- `PGATE`, `NGATE` — средняя мощность во **внешнем** gate resistor;
- `PFET`, `NFET` — средняя электрическая мощность каждого MOSFET;
- `P_TR/P_TF`, `N_TR/N_TF` — 10–90 % / 90–10 % фронты gate voltage;
- `SW_TR/SW_TF` — 10–90 % / 90–10 % фронты midpoint;
- `DT_PN`, `DT_NP` — фактический gate-threshold margin между выключением
  одного и включением второго плеча.

Именно совокупность этих параметров даёт «золотую середину»: слишком малый
`Rg` уменьшает время переключения, но увеличивает пики тока/EMI; слишком
большой `Rg` снижает пики, но растит switching loss и в конце концов не даёт
затвору/узлу установиться на высокой частоте.

`run_sweeps.sh FDS4559` сохраняет QPOST-результат и дополнительно строит CSV,
где одна строка соответствует одному значению `FSW`.

### Производительность sweep

Switching sweep специально не сохраняет весь внутренний state VDMOS. В netlist
есть явные `.save` только для узлов и токов, которые нужны `.meas`. Это важно:
QPOST работает **после** формирования `.qraw`, и без ограничения сохранённых
трасс многомерный transient легко порождает файл на сотни мегабайт.

Стенд моделирует 3 периода на каждую частоту, а измерения выполняются на
2-м/3-м периодах. Параметр:

```spice
.param TMAX=50n
```

задаёт верхнюю границу шага на плоских участках. QSPICE остаётся адаптивным и
уменьшает шаг около 1-нс фронтов и нелинейных переключений. Не следует без
необходимости возвращать фиксированный `10 ns` на протяжении сотен микросекунд:
это почти не добавляет информации, но резко увеличивает `.qraw` и время QPOST.

По умолчанию `run_sweeps.sh` удаляет `.qraw` после QPOST/CSV. Для просмотра
осциллограмм:

```bash
KEEP_RAW=1 ./run_sweeps.sh FDS4559
```

## Ограничения модели — обязательно учитывать

Этот sweep **не является гарантией допустимой частоты реального устройства**.
Он показывает пределы текущей электрической модели и выбранной fixture.

### 1. Reverse recovery body diode не верифицирован

Даташит FDS4559 не задаёт `Qrr` / `trr`, поэтому при генерации модели эти
параметры не были выдуманы. Следовательно, нельзя использовать этот sweep
для точного прогноза:

- reverse-recovery current spike;
- reverse-recovery energy;
- минимального hardware dead-time после проводимости body diode.

`DT_PN/DT_NP` — **gate/capacitance margin**, а не окончательный безопасный
 dead-time железа.

### 2. Package/PCB parasitics отсутствуют

В модели нет измеренных индуктивностей выводов, дорожек, общего истока и
конденсаторов шины конкретной платы. Поэтому абсолютные значения ringing,
`dV/dt`, `dI/dt` и EMI на реальной PCB этим стендом не подтверждаются.

### 3. Драйвер идеальный

Источник gate voltage идеален; исследуется именно зависимость от внешнего
`Rg` плюс внутреннего `Rg=9 ohm` модели. Реальный driver добавит своё
выходное сопротивление, асимметрию source/sink, задержку и температурный
разброс. Это уже задача application-level bench.

### 4. Self-heating не моделируется

`.temp` задаёт температуру перехода извне. Модель не содержит thermal RC
корпус → PCB → ambient, поэтому не вычисляет рост `Tj` от собственных потерь.

### 5. Температурная модель откалибрована по двум anchor points

`RDS(on)` точно привязан к 25 °C и 125 °C через `Trs1/Trd1`. Поведение между
ними — интерполяция модели, а ниже 25 °C — экстраполяция. Это полезно для
анализа, но не является статистической гарантией каждого экземпляра.

### 6. VGS(th) — nominal fit, не точный Typ

Обе модели проходят гарантированные Min/Max, но `VGS(th) Typ` остаётся WARN.
Поэтому threshold в `DT_PN/DT_NP` используется как **повторяемый marker**,
а не как прецизионная физическая граница проводимости.

### 7. Avalanche / работа у absolute maximum не верифицированы

Наличие `Vds=60` в модели не означает подтверждённую avalanche-модель.
Стенд специально работает далеко от breakdown.

## Как выбирать Rg по результату

Сначала отбрасываются режимы, где:

- `DT_PN <= 0` или `DT_NP <= 0`;
- gate не достигает примерно 90 % заданной амплитуды;
- midpoint не достигает обеих шин;
- switching time становится значимой частью полупериода.

Из оставшихся сравниваются:

```text
Ptotal ~= PFET + NFET + PGATE + NGATE
```

вместе с `IBUS_PK`, `SW_TR/SW_TF` и запасом dead-time.

После выбора 2–3 кандидатов делается отдельный **dead-time sweep** уже в
целевом приложении или в следующем универсальном bench. Финальный dead-time
всё равно подтверждается осциллографом на PCB из-за отсутствующего Qrr и
паразитных индуктивностей.
